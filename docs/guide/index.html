Getting started

Markover opens agent-written Markdown as a navigable document tree, stores feedback on individual blocks, and returns one structured review to the agent thread.

Preview status

Markover is a free, MIT-licensed early preview for macOS. It requires no account, and review data stays on your Mac.

The current release runs on Apple Silicon and Intel Macs and requires Node.js 22.13.0 or newer for the launcher. You do not need to clone the repository or install an npm package globally.

Release status. The app is ad-hoc signed, not Developer ID signed or notarized. macOS may ask you to confirm opening an app downloaded from the internet.

Launch Markover

Give the versioned launcher a Markdown file and a short summary of the review you need:

npx --yes \
  --package=https://github.com/lastobelus/markover/releases/download/v0.1.1/markover-cli.tgz \
  markover open ./DOCUMENT.md \
  --summary "Review these decisions before implementation."

On first use, the launcher downloads the app for the current Mac architecture, verifies its SHA-256 checksum, and keeps the verified app in a local cache. The command opens the document and exits with one JSON value:

{"reviewId":"mko_8f3a2c","status":"editing"}
Use the complete URL. The public npm package named markover is unrelated. Do not run npx markover or npm install markover.

Set up an agent

The CLI lifecycle is provider-neutral for agents with macOS shell access. Markover does not claim tested integration with every agent. The focused preview verifies the repository-instruction workflow with Codex and T3 Code.

Generic instructions

Adapt this block to the durable instruction surface your agent uses:

When I ask you to open a Markdown document in Markover:

1. Run the full versioned launcher with `open <path> --summary "<purpose>"` once.
2. Retain the returned review ID, tell me the review is ready, and stop.
3. Do not poll. Wait until I say “Check Markover” or clearly request retrieval.
4. Run the same launcher with `get <reviewId>` once.
5. Implement clear revisions, answer questions without silently editing,
   respond to discussion, ask about ambiguity, and inspect every attachment.
6. If I need to amend feedback, run `edit <reviewId>` and wait again.

Use the complete package URL from Launch Markover for every open, get, or edit command.

Codex and T3 Code

Add the same lifecycle to the repository-root AGENTS.md. When the current surface exposes a thread ID, pass --thread-id <id>. Otherwise generate 16–64 random letters or digits and pass --handoff-key mko_handoff_<random-value>. This lets Markover preserve agent-thread provenance without requiring an account.

After retrieval, treat an exact source proposal as a requested revision unless its feedback frames it as an option or question. Use edited attachment labels and inline [!label] references to understand screenshot-backed feedback.

Review a document

Select a block in the document tree and write Markdown feedback in the annotation pane. Paste screenshots directly into the feedback field; each paste inserts an inline reference such as [!img-1]. Control-click an attachment to give it a descriptive label, and Markover updates its inline references.

The documents list keeps multiple reviews grouped by project. Use All annotations to read the active document's feedback as a single rendered list, or Annotated to filter the document tree to commented blocks.

Editing a source block creates a proposal. Markover preserves the original source and shows the proposed change as a word-level diff.

Return the handoff

When the reviewer says “Check Markover,” retrieve the review once with the ID returned by open:

npx --yes \
  --package=https://github.com/lastobelus/markover/releases/download/v0.1.1/markover-cli.tgz \
  markover get mko_8f3a2c

get freezes the latest review, marks it read-only in Markover, and returns one JSON object containing the exact source and checksum, document tree, annotations, attachments, source proposals, and review context.

If the reviewer needs to add or correct feedback, return the same review to editing:

npx --yes \
  --package=https://github.com/lastobelus/markover/releases/download/v0.1.1/markover-cli.tgz \
  markover edit mko_8f3a2c

After edit, the agent must wait for another explicit retrieval request rather than polling.

Keyboard controls

KeyAction
Up / DownMove between sibling blocks; climb outward at a boundary
LeftSelect the parent block
RightSelect the first child, then the next available sibling
Tab / Shift-TabMove between the document and annotation panes
Control-Tab / Control-Shift-TabMove between open documents
EnterEdit the selected annotation from the all-annotations view

Double-click a block, or use its disclosure control, to collapse or expand its children.
