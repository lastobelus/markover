Markdown support and preview limitations

Markover preserves the original Markdown while turning the structures it understands into selectable review blocks. Some structures are selectable only as a whole, and extension-specific syntax may remain ordinary or literal content.

Selectable document structure

Markover creates review-tree structure for YAML frontmatter, headings, paragraphs, ordered and unordered lists, task markers, fenced and indented code blocks, thematic breaks, tables, and block quotes.

Headings and nested lists organize the tree. Paragraphs, tasks, code, and thematic breaks can be selected and annotated as individual blocks.

Tables and block quotes are whole blocks

Tables and block quotes render and can be selected for feedback, but their internal rows, cells, and quoted children do not become separately selectable review-tree nodes.

Practical consequence. Attach feedback to the complete table or quote. If row-level or nested-quote feedback matters, describe the exact row or passage in the annotation.

Extensions may lose specialized meaning

Footnotes, definition lists, strikethrough, raw HTML, and other Markdown extensions have no specialized review structure. Depending on the syntax, they may appear as ordinary CommonMark content or literal text.

Do not rely on Markover's preview as the authoritative renderer for a site-specific or extension-heavy Markdown dialect. Compare important formatting in the tool that will publish or consume the document.

Links stay inert; remote images require consent

Rendered links do not navigate when clicked in a review. A remote HTTP or HTTPS image starts as an inert preview button. Markover requests it only after you explicitly choose to preview it; the image host then receives ordinary request metadata, including your IP address.

Local pasted screenshot attachments are stored with the review. Inspect attachments and review content before sharing a handoff.

The original source remains the reference

Markover retains the exact reviewed Markdown and its checksum even when it cannot give extension-specific syntax its own tree structure. Editing a source block creates a proposal; Markover does not rewrite the original review target.

A complete handoff therefore preserves the source for an agent or developer to inspect rather than pretending every syntax feature was represented perfectly by the preview.

Early-preview product boundary

  • Markover supports macOS 14 Sonoma or newer on Apple Silicon Macs. Native Intel releases are deferred to the Broad announcement roadmap.
  • The launcher requires Node.js 22.13.0 or newer.
  • Current downloads are hardened and ad-hoc signed, but not Apple-verified or notarized.
  • Review formats may change without migration guarantees. Historical JSON and attachments are preserved, but a newer app may not open every older review.
  • Review deletion and cache management currently use the manual procedures in Privacy, storage, and recovery.

Ask about a document or report a defect

Use GitHub Discussions when you are unsure whether a document or syntax will work well. Use the bug report form for a reproducible defect, including the smallest sanitized example that demonstrates it.
