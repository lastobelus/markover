Privacy and local data

Markover keeps ordinary review work on your Mac. This page explains what “local” means, what is stored, which deliberate actions can use the network, and what leaves Markover when you hand a review to an agent.

Local means your macOS account

Markover stores reviews and runs its loopback API inside the current macOS account. Each account—including accounts active through Fast User Switching—runs an independent Markover instance with separate data, endpoint records, and credentials.

The application-data directory is restricted to its owner on supported macOS systems. A process running as another ordinary account can connect to loopback but cannot read Markover's protected capability, so the API denies it.

The trust boundary is the OS account. Other processes running as you, system administrators, and root can ordinarily read your files or credentials and remain inside this boundary. Markover does not claim to isolate data from them.

How the local API is protected

Each Markover service process creates a fresh 256-bit capability. The application-data directory uses POSIX mode 0700, while service.json and service.token use 0600. Every review route requires that capability before route handling or request-body processing.

Exact GET /health is public and returns only service status, protocol version, and a temporary instance ID. The instance ID is a non-secret name tag that helps the client avoid sending its capability to an ordinary unrelated listener. It is not authentication or cryptographic proof against a process already running as you.

Rejected-request diagnostics are off by default. If enabled in Settings, they contain only the method, path without its query, and a coarse rejection reason—never the capability, authorization field, request body, or review content.

What Markover stores

A review can contain the complete Markdown source, parsed document structure, annotations, source-edit proposals, attachment files and metadata, review state, and timestamps. Proposed source edits stay in the review; Markover does not apply them to the original Markdown source.

When available, provenance can include source and repository paths, a sanitized Git remote, branch, commit, pull-request number, and agent-thread details such as IDs, working directory, parent or fork information, and the selected local session-log path.

Local does not mean safe to publish. Review JSON, attachments, and otherwise legitimate command output can contain private content and identifying paths or IDs. Inspect or sanitize them before sharing.

Where data lives

On macOS, Markover's per-user root is:

~/Library/Application Support/Markover/

Managed reviews live under reviews/<review-id>/. Each directory contains review.json and, when present, attachment files. The root also contains settings.json and temporary service discovery records named service.json and service.token.

Local provenance discovery

Markover may run read-only Git commands beside the reviewed source to record repository root, sanitized remote URL, branch, and commit. URL credentials, query strings, and fragments are removed before a URL-style remote is retained.

If an agent supplies a unique handoff key but no explicit thread ID, Markover can search a bounded set of recent local Codex session records for an exact match. It stores selected provenance from one unambiguous match, not a copy of the scanned logs.

This search is enabled by default. Turn off Discover agent thread from local session logs in Markover's Privacy settings to skip it on subsequent open commands. Explicit thread IDs and Git provenance remain available.

When an agent retrieves a review

An authenticated get returns the review source, annotations, attachments metadata, provenance, and agent guidance to the requesting local agent. Markover itself does not upload that handoff.

After another agent or tool receives the data, its storage, logging, sharing, and network behavior are outside Markover's control. Apply that recipient's privacy policy and trust model as well as Markover's.

When the internet may be used

Ordinary review handling has no telemetry, analytics, cloud synchronization, or automatic upload of review content.

  • Installing or updating through the launcher can download packages and release files from npm or GitHub.
  • A remote Markdown image starts as an inert preview button. If you explicitly open it, Markover requests its HTTP or HTTPS URL. The image host receives ordinary request metadata, including your IP address.

These user-triggered connections are why Markover does not claim that it never connects to the internet.

Retention and deletion

Reviews and attachments remain until you remove them. Markover does not currently provide in-app review deletion.

For temporary manual deletion, first quit Markover. Then remove only the relevant directory under ~/Library/Application Support/Markover/reviews/. Quitting first prevents active in-memory state from writing that review again. A safer in-app deletion flow is tracked separately.
