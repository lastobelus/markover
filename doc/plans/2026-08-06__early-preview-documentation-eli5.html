The Tiny Story

Think of the documentation as two adjoining rooms. The user room explains choices, actions, consequences, limitations, and help. The developer room explains mechanisms, invariants, tests, and release operations. A labelled door connects them, but nobody must cross it to finish ordinary work. The same truth may be written twice when that is clearer than making one audience decode the other's version.

Two roots, two reading paths

Deployed

docs/user/

The Pages artifact root. It contains the website, setup guide, privacy/storage/recovery reference, Markdown limitations, assets, and user support links. Technical detail appears only when it changes a user's decision or action.

Repository

docs/developer/

The contributor root. It contains development setup, release operations, local-service security mechanics, architecture, evidence, source pointers, and maintenance invariants. It is not deployed to Pages.

Cross-links are optional and clearly labelled. Shared prose machinery is deliberately absent.

Two checkpoints, one evidence gate

The accepted design contract in #39 is not publication evidence. Its tested result becomes a concise user promise and a deeper developer evidence record.

Where each answer lives

User entry

README + user guide

A compact “Before you try the early preview” summary gives the maturity label, requirements, trust status, data boundary, compatibility warning, and optional next links.

User data

Privacy, storage, and recovery

The user page explains stored data, consequences, cleanup, recovery and the account trust boundary without capability bit lengths, file modes, route order, or diagnostic internals.

User boundary

Markdown support and limitations

The user page describes what can be selected and annotated, what stays whole, and how extensions degrade—without parser names or review-tree implementation contracts.

Developer entry

Contributor index

docs/developer/README.md routes builders to setup, tests, architecture, security, release operations, decisions, and the user contract their work must preserve.

Developer detail

Security and durability mechanics

Exact capabilities, file modes, routes, diagnostics, persistence invariants, test scenarios, and evidence locations live here rather than cluttering the public privacy page.

Connection

Labelled cross-links

User pages may offer a “Technical details for contributors” link. Developer pages link back to the public promise. Neither side delegates its essential explanation to the other.

The important guardrail

Audience clarity beats prose deduplication. This work does not add shared fragments, transclusion, a documentation framework, legacy-path redirects, or a mixed catch-all root. It also does not create migrations, deletion UI, telemetry, authorization changes, durability behavior, Markdown extensions, or release machinery.
