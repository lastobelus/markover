Proposed stack after PR #195

Make every public picture look like the product again.

Markover's application has a new Ember Light interface, but the website, README, screenshots, banner, and launch assets still show the old one. This plan updates the sources first, captures the real app second, and publishes only after everything agrees.

Where this is true Proposed · August 28, 2026

This page explains the draft umbrella plan based on merged PR #195, open roadmap issue #16, and the stale preparation in PR #51. The exact stack may be refined in review, but its stable boundary is public visuals and reproducible media capture—not application behavior or announcement operations.

The tiny story

01 · NOW

The app moved on

The real product has a shorter header, left-side review navigation, three panes, and updated Ember Light surfaces.

02 · GAP

The public story did not

Four screenshots, the Pages mockup, README leader, and GitHub preview still describe the retired interface. No demo exists.

03 · FIX

One staged source, many truthful outputs

A sanitized real-app fixture feeds current screenshots and a short movie; the same Ember roles shape Pages, README, and social cards.

How the pull requests fit

Each child is independently reviewable. Later media depends on the visual and staging decisions below it, so the stack stays linear.

What each slice contributes

FOUNDATION

Safe, repeatable staging

  • Disposable state—never the user's real reviews.
  • Invented projects, paths, thread IDs, attachments, and Git metadata.
  • Production branding with no development badge.
  • Exact commit, window, theme, and output manifest.
THEME

One Ember Light language

  • SF/system typography and current ground, paper, and quiet panes.
  • A responsive three-pane HTML hero—not a fake raster.
  • Updated README leader, social cards, and undated brand references.
STILLS

Four real application states

  • Editor with labeled attachments.
  • All annotations in Projects navigation.
  • Exact source proposal diff.
  • Sanitized review context.
MOTION

One complete review loop

  • 30–60 seconds, silent, captioned, 1080p H.264.
  • Open, annotate, show attachment, propose edit, retrieve handoff.
  • Pages embed and transcript; README poster link.
  • Verified GitHub description, homepage, topics, card, and pins.

How we know it is real

Machines verify

Dimensions, density, hashes, asset references, social-card size, video codec/frame rate/duration/fast-start, documentation tests, local CI, and clean diffs.

People verify

Current #195 chrome, Ember Light fidelity, legibility, private-data absence, video pacing, README light/dark rendering, Pages desktop/narrow layouts, and live GitHub previews.

What stays outside

  • No product behavior changes just to improve a capture.
  • No screenshot service, recording daemon, generic fixture framework, or compatibility path.
  • No real review data, private metadata, or AI-edited application pixels.
  • No rewriting clearly dated historical design artifacts.
  • No announcement posting or feedback operation; those remain with issues #17 and #18.
  • No early closure of issue #84's late human editorial pass.

Roadmap handoff

#16 comes in

The umbrella owns the public visual assets, demo, README examples, social cards, and verified repository metadata.

#51 is superseded

Its useful generator, manifest, storyboard, and transcript ideas are rebuilt on current main; its old UI outputs are discarded.

#84 stays late

This stack gives the later editorial pass current screenshots, links, commands, and responsive layouts without pretending post-preview feedback already happened.

#17 and #18 stay downstream

They consume the finished kit for announcement operations. They do not own the asset implementation.
