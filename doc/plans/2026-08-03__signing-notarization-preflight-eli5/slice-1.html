Issue 13 · Slice 1

Inspect the exact box before shelving it.

Slice 1 replaces a broad final signing shortcut with component-by-component signing, then makes both the release verifier and bootstrap reject anything that does not match Markover's declared ad-hoc contract.

Where This Is True PR #45 merged · Implemented on main · 5 Aug 2026

This is the implemented and accepted slice 1 of the reviewed issue 13 plan through PR #45, merged 4 August 2026 and rechecked 5 August 2026. It applies to native macOS packaging and first bootstrap installation, not GitHub publication or future Apple credentials.

Stable center

Explicit ad-hoc trust mode, hardened runtime, minimal entitlements, strict final-ZIP verification, and fail-closed installation.

Expected to change

Merged slices 2 and 3 preserve this package contract. The public bootstrap and release set now select Apple Silicon only; x64 verification primitives remain for deferred issue #80. Future Developer ID activation changes expected identity and Gatekeeper results. Re-check PR #45, issue #13, issue #80, and the plan.

The Tiny Story

Markover used to pack the whole moving truck, then put one broad seal over it with codesign --deep. Slice 1 now seals each important box in the right order, writes down exactly which special permissions each box needs, and inspects the final truck at the destination.

The bootstrap does not trust “the filename looked right.” It verifies the checksum, extracts into staging, inspects the app, and only then performs the atomic move into the versioned cache.

The package-to-install flow

Every mutation happens before signing. Every mismatch exits through the reject lane.

What the inspectors know

Identity

The app is Markover

The final-ZIP verifier and first-install bootstrap check the expected filename, app and helper bundle IDs, version, every embedded Mach-O architecture, and LSMinimumSystemVersion = 14.0.

Seal

Every signed component agrees

The final ZIP and first-install bootstrap enforce strict code seals, hardened-runtime flags, ad-hoc identity, and no Team ID on embedded executables; the final ZIP also enforces exact entitlements.

Permissions

No surprise capabilities

Only narrowly justified Electron runtime permissions are allowed; device and personal-information defaults are rejected.

Policy truth

Gatekeeper still says no

That rejection is expected in ad-hoc mode and reported honestly; it is not confused with a broken internal seal.

What slice 1 does not do

  • It does not notarize, staple, publish, version, tag, or alter GitHub settings.
  • It does not claim an authenticated publisher or hide the Gatekeeper warning.
  • It does not add a DMG, universal binary, updater, rollback UI, or App Sandbox.
  • It does not duplicate issue #12's auth fixture or issue #39's durability tests.

What passed locally

  • Deterministic unit tests exercise unsafe paths, malformed metadata, component and embedded-binary architecture mismatch, signature mismatch, entitlement drift, command failure, and cleanup.
  • A real arm64 package was produced on macOS; its exact final ZIP passed the native verifier, including expected Gatekeeper rejection.
  • Lint, type checking, notices, and all 197 tests pass after merging current main.
  • The implementation and this ELI5 are updated together and stop at the slice-1 review boundary.
