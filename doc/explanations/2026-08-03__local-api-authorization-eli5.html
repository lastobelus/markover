A locked note, a name tag, and an honest meaning of “local”

Markover keeps review work inside your macOS account and puts one capability check in front of every review route. This page explains the lock, the calm repair path, what is stored, and where Markover’s guarantee ends.

The Tiny Story

The lock

Every review request needs a short-lived capability stored where another ordinary macOS account cannot read it.

The name tag

Before sending that capability, the client checks that the listener matches the instance named by its files. Broken records can be republished in place.

The honest limit

A process already running as you can read the same files. Markover does not pretend to defend against that process, an administrator, or root.

Before a secret leaves disk

Every authenticated operation performs this preflight afresh. A failed name-tag check stops before the Bearer token or review request is sent.

ID

The instance ID is a name tag, not a lock. It catches ordinary stale or unrelated listeners before a secret is sent. Because health exposes it publicly, a deliberately prepared malicious listener could copy it. Preventing that would require a more complex authentication design, which is deferred until Markover’s real deployment needs justify it.

One gate in front of every review route

One public peephole

Exact GET /health reveals status, protocol version, and the non-secret instance name tag. A query or different method is no longer that exact public request.

Everything else is locked

List, import, create, read, handoff, edit, and even unknown routes must present the capability before Markover chooses a route or reads JSON.

One boring denial

Missing, malformed, duplicated, and incorrect credentials all receive the same 401. They cannot use errors to map routes or trigger mutations.

One recovery signal, three outcomes

The CLI never decides to kill Markover. It sends the same background launch-or-notify signal once and waits for a complete healthy pair.

What changes—and what does not

Repair while running

The primary rewrites the protected pair from memory. No identity rotation, review reload, new window, or process restart.

Real process restart

A new instance ID and capability are generated. Historical reviews stay in their existing storage.

Ambiguous request failure

The client does not replay it. For open, a replay could create a duplicate review; inspect Markover first.

What “local” includes

Stored on this account

Review JSON can contain the full Markdown source, annotations, proposals, attachments, local paths, Git details, and agent-thread provenance. Local does not mean automatically safe to share.

Original source stays put

A source edit is a proposal inside the review artifact. Markover does not apply it to the original Markdown file.

Optional local discovery

A bounded exact-key search can associate a review with a recent Codex session. The default-on Discover agent thread from local session logs Privacy setting can disable that search without disabling explicit thread IDs or Git provenance.

One process per macOS user

Fast User Switching can leave separate Markover instances running. Each user gets separate application data, endpoint files, capability, and reviews.

Two deliberate network edges

Ordinary reviewing

No telemetry, analytics, cloud sync, or automatic review upload.

Install and update

The launcher can download packages and release files from npm or GitHub.

Remote images

A remote Markdown image starts as an inert button. Clicking preview requests its host, which receives ordinary request metadata such as your IP address.

→

An agent handoff crosses the Markover boundary. Markover does not upload the review, but an authenticated get gives its contents and metadata to the requesting agent. What that recipient stores, logs, or transmits is governed by the recipient—not Markover.

Guardrails against overengineering

Not added

  • Same-user isolation or cryptographic server proof
  • Local TLS, certificates, Unix sockets, daemons, or new dependencies
  • Fuzzing, load machinery, compatibility readers, or speculative migrations
