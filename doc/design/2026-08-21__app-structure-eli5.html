Markover design vocabulary

App structure, from the outside in

Six structural names describe the frame from the outside in. Region names describe where something is, while the contents inside keep describing what they do.

Where This Is True Accepted · PR 195 · 2026-08-21

This page explains the accepted first-level structure for Markover's desktop app. The canonical contract lives in docs/developer/app-structure.md. Later passes will name the contents, components, dialogs, and settings nested inside these regions.

The Tiny Story

Today, code names top-level panes after whatever they happen to contain. The new vocabulary separates the frame from its furniture: a pane keeps its structural name even when its contents change.

The complete first level

The app shell contains one app header and one pane layout. The pane layout contains exactly three positional panes.

One name across every layer

appShell · .app-shell · --app-shell-background

App header

appHeader · .app-header · --app-header-background

Pane layout

paneLayout · .pane-layout · structural container

Right pane

rightPane · .right-pane · --right-pane-background

The naming rule

A pane name identifies only its stable place in the app shell. Review navigation, document tree, and annotation views identify content hosted inside a pane.

Prompt/context Why this page exists

The UI-improvement takeover began because top-level app regions, their contents, and their color tokens had accumulated conflicting names. The maintainer accepted a spatial, content-neutral vocabulary and asked for the same names in the glossary, documentation, code architecture, and theming system.
